# What counted as a scope error?

A reader assigned **yes** when the trace showed an agent treating evidence from a narrower or different set of entities, dates or search results as sufficient for the requested scope. A wrong value, failed navigation, an incompletely explored page or a missing answer alone was insufficient. **No** means the reader found no positive evidence meeting the criterion. **Unclear** means the evidence left the classification unresolved. The agent can treat the task as solved in its reasoning even when it never sends a final answer.

The audit covers every run on which the two automatic graders disagreed in this sample. The motivating Qwen run on task 15 is included and identified separately. We shuffled the cases using seed 117. Two first-pass readers split them 31/31. A separate reader classified all 62 without seeing those ratings. All readers were model instances given the same written criterion. Their packets contained the goal, recorded actions and observations available to the original language grader. We withheld the identifying file paths, grader completions, functional scores and expert labels. We did not edit the source text to remove incidental clues.

We retain both initial judgments and explanations. The headline count requires both readers to say yes, the language grader to pass the run and the published expert to mark it unsuccessful. This links a trace-level diagnosis to a scoring disagreement. The expert label concerns task success. It does not say why the task failed or certify the readers’ diagnosis. The study uses observational traces and cannot isolate which signal caused the grader to pass the run.

To reproduce, run `python3 study.py`, then `python3 audit.py`. To conduct a fresh review, run `python3 review_packets.py .cache/my-review` and give the new packet directory and first paragraph of this rubric to the reader. Each record in audit.json links to decisions.csv by task and agent. The explorer links to the immutable original judgment for every run.
